# 糯糯 v4 设计说明：竖屏、每个互动都有反应、悬念与解压

> 本文说明 v4 "为什么这样改"。v4 不是凭空加功能，而是照着一次真实直播测试暴露的问题改的；每条改动后面是它参考的成熟做法。
> 闯关元素、任务站、镜头、画风、声音的设计见 [设计说明-v3.md](设计说明-v3.md)，这里不重复。

## 1. 实测暴露的问题 → 根因 → 改法

| 实测现象 | 根因 | v4 的改法 |
|---|---|---|
| 新眼睛不好看 | 上一版换的琥珀色"动画电影眼"不如原来的紫色大眼睛讨喜 | 恢复原来的眼睛（保留了后来修好的"压扁时眼睛不变形"） |
| 手机上看不清 | 画面按横屏 16:9 设计，文字分布在四角；抖音观众竖着看，横屏画面只占屏幕中间一小条 | 默认竖屏 9:16，界面和镜头按竖屏重排（第 5 节） |
| 发弹幕、送礼物没反应 | 两层原因。**监听层**：只认网址里带固定字样的连接、漏掉监听开始前建立的连接；监听浏览器是隐藏的，停在验证码 / 登录页 / 别人的直播间 / 未开播页面时没有任何提示。**游戏层**：礼物要等糯糯走到两段之间才答谢（赶上做任务要等半分钟），普通弹幕和点赞几乎没有画面反馈 | 监听重写 + 连接体检（第 6 节）；所有互动半秒内有反馈（第 3 节） |
| 内容重复、留不住人 | 一关只有"解压站 + 闯关元素"两种节奏，结果完全可预期；没有任何"接下来会怎样"的问题，也没有跨关的长期目标 | 加入悬念段落、解压新段落、盲盒图鉴（第 4 节） |
| 观众不送礼物 | 玩法的唯一输入是礼物；不花钱的观众只能看 | 所有免费互动都变成「应援值」，推动应援条和悬念的结果（第 3 节） |
| 来的都是小朋友 | 主要是投放和时段问题（可爱画风 + 通投 + 白天开播）；内容里也没有成年人的"梗" | 内容上加入打工人烦恼、盲盒收集；运营上的做法单独写在 [运营建议.md](运营建议.md) |

## 2. 调研结论（成熟做法 → 我们怎么用）

| 成熟做法 | 公开资料里的关键点 | 在糯糯里的落地 |
|---|---|---|
| **抖音弹幕互动玩法**（阵营对抗类） | 观众发弹幕「1」或「2」就加入一方；点赞、礼物都能直接影响战局；排行榜刺激大家持续参与。报道同时指出：愿意付费的只是少数重度用户，大多数人只做免费互动 | 投票统一用最简单的字：`1` `2` `3`、`左` `右`；所有免费互动都能影响结果；「应援榜」把点赞、弹幕也算进去。没有做成两队对抗，而是"大家一起帮糯糯"——更贴合解压、治愈的调性 |
| **修勾夜店**（评论即生成自己的角色） | 观众输入指令，画面里就多一个属于自己的小角色——从"看别人玩"变成"我在里面"，这种参与感是留人的关键；后续报道提到新鲜感会衰减，要靠换场景、换装扮、做活动维持；在抖音也遇到过封号风险 | 观众的**字和昵称出现在画面里**：烦恼泡泡带「@昵称」、应援条攒满点名、MVP 点名、投票飘字。用 8 个世界轮换 + 35 款图鉴对抗新鲜感衰减。合规风险写进手册 |
| **直播间流量逻辑**（运营文章的共识，非官方文档） | 评论、点赞、关注、加粉丝团都是互动指标，其中最重要的是**停留**；本场数据会影响后面的推流 | 每 40~60 秒安排一个"钩子"（投票、开盲盒、砸宝箱倒计时）让人多留一会儿；每一种互动都有即时反馈，鼓励观众去做 |
| **盲盒 / 扭蛋 / 图鉴收集** | 不确定的奖励 + 看得见的收集进度（"就差一个"）；成年人非常熟悉 | 盲盒蛋 + 35 款图鉴（7 系列 × 5 款，4 种稀有度）；没开到过的款优先出，让进度看得见地往前走；直播间越热越容易出稀有款 |
| **综艺闯关里的"二选一 / 三选一"**（《鱿鱼游戏》玻璃桥式的"哪块是安全的"、三扇门选一扇） | 选择 → 等待 → 揭晓，是最便宜、最有效的悬念结构 | 脆脆桥（左 / 右，踩错掉进软软的云里再弹回来，可爱、不吓人）、三选一礼盒（大奖 / 小奖 / 整蛊，最后把另外两个也打开——"原来大奖在 3 号"） |
| **进度条 + 倒计时的集体目标**（直播间常见的"点赞到 X 就 Y"、平台福袋的倒计时） | 一个所有人都能出力、有明确时限的目标，最容易带动免费互动 | 应援条（长期）；终点宝箱（12 秒冲刺，点赞弹幕都算力气）；开盲盒时的「稀有加成」条 |
| **"把烦恼写下来再毁掉"、多米诺连锁** | 解压内容里长盛不衰的两类：有情绪出口的破坏，和一触即发的连锁反应 | 烦恼泡泡（观众写的烦恼被一脚踩扁）；多米诺骨牌（30 块一路倒到底，每块配真实的"哒"声） |
| **平台对"录播 / 挂机"的治理** | 平台强调直播要真实、实时、可互动；录播、定格画面、几乎没有互动、无真人出镜都在治理范围内 | 互动即时反馈本身就是"可互动"的体现；文档里明确建议有人在场、不要纯挂机 |

## 3. 互动系统

### 3.1 一条互动的旅程

```
直播间事件（点赞 / 弹幕 / 关注 / 粉丝团 / 分享 / 进房 / 礼物）
   │  server/points.js 算出应援值 pts（礼物 1 抖币 = 10，点赞 1，弹幕 3，关注 30，粉丝团 50，分享 20）
   │  计入今日应援榜（进房不上榜），SSE 推给游戏
   ▼
web/js/game/interaction.js
   ├─ 立刻的画面反馈（飘字、爱心、提示条、"收到礼物"卡片、粒子）
   ├─ 应援条 +pts（cheer.js）→ 攒满 → 点名 → 下一个空档掉盲盒
   ├─ 弹幕分流：正在投票 → 算一票；指令 / 世界名 → 导演 AI；像烦恼 → 进烦恼队列；其它 → 只算分
   └─ 礼物进答谢队列（giftManager.js）→ 最近的安全点跳舞
```

"立刻"是硬指标：以前礼物的第一反应可能在几十秒之后，观众会以为没收到。现在反馈分两层——**即时层**（半秒内，纯界面和粒子，不打断糯糯正在做的事）和**演出层**（跳舞、掉盲盒、踩泡泡，排在最近的安全点）。

### 3.2 应援条：让冷清和热闹的直播间都好玩

固定长度的进度条有个老问题：人少时永远攒不满，人多时几秒钟刷满。应援条的长度是自适应的：

- 每次攒满后，按**最近一分钟观众贡献的速度**重新定下一条的长度，目标是大约 90 秒满一次：`目标 = 限制在[70, 8000]之间(每秒应援 × 90)`，再和当前长度做平滑（新 = 旧 + 0.6 ×（目标 − 旧））。
- 糯糯自己踩的每一脚算 0.5：没人互动时每关也能攒出一个盲盒，画面不会干等。
- 攒满的盲盒最多存 2 个，两次掉落至少间隔 40 秒：不会变成"一直在开盲盒"。
- 一份大礼物可能一下子超过好几条的长度：只算满一次，条停在九成，不无限连开。
- **热度** = 最近 30 秒观众的应援 ÷（半条应援条）。它会提高开盲盒的稀有度、参与终点宝箱的进度——免费互动由此真正影响结果。

### 3.3 为什么分数在服务器算

一处定规则（`server/points.js`），应援榜、应援条、控制台都用同一个数；防刷规则也在这里：一条点赞消息最多算 50 个；同一个人 20 秒内最多 4 条弹幕算分。游戏页面刷新、重启都不影响榜单。

### 3.4 观众的字上屏之前

烦恼泡泡会把观众的字做进 3D 画面，所以宁可错杀：最多 8 个字；含 3 位以上数字、网址、@ 的不要；联系方式、广告、脏话、敏感词不要；只留中文、字母、数字；`左` `右` `1` 这类投票用字不当成烦恼。被过滤的弹幕照样算应援值。可以整体关闭（`game.chatOnScreen`）。

## 4. 关卡节奏：解压 → 悬念 → 揭晓

```
解压站① → 烦恼泡泡 → 闯关元素① → 解压站② → 盲盒蛋 → 解压站③
        → 三选一礼盒 / 脆脆桥 → 闯关元素② → 多米诺（约六成）→ 巨型终点 → 终点宝箱
```

- **解压段**提供"舒服"（可预期、有韵律），**悬念段**提供"想知道结果"（不可预期）。两者交替，观众不会一直紧张，也不会一直走神。
- 一关约 4 分钟，悬念点大约落在第 1 分钟（盲盒蛋）、第 2~3 分钟（投票）、最后（宝箱）。新观众无论什么时候进来，一分钟之内都会遇到一个"我可以参与、马上有结果"的时刻。
- 每个悬念段都遵守同一个三拍：**提出问题**（面板 + 倒计时）→ **卖关子**（礼盒抖三下、蛋一道道裂开、进度条一格格涨）→ **揭晓**（大字卡片 + 粒子 + 糯糯的反应），失败也要好看（整蛊的弹簧小球、掉进云里弹回来、"只裂开了 87%"）。

| 段落 | 时长与数值 | 设计意图 |
|---|---|---|
| 盲盒蛋 | 敲 3 下，约 5 秒；这几秒里的点赞直接加「稀有加成」 | 不需要打字的参与方式：点赞。结果立刻可见 |
| 三选一礼盒 | 投票 9 秒；大奖 / 小奖 / 整蛊各一个，位置随机；一人一票可改票；猜中大奖的每人 +20 | 三个选项 = 三种情绪（惊喜、还行、好笑），没有"失败" |
| 脆脆桥 | 3 排，每排投票 6 秒；全对奖励盲盒，全对的观众 +20 | 连续三次小悬念；随便选全对的概率是八分之一，"差一点"很常见 |
| 终点宝箱 | 12 秒；糯糯自己的力气每关随机（不靠帮忙约四成能砸开），观众的应援直接加进度 | 结尾必须有真悬念：不是每次都成功，但大家出力就基本能成 |
| 烦恼泡泡 | 5 个泡泡；观众写的优先、带昵称；没有就用内置的打工人清单 | 观众的字被"处理掉"——情绪出口 + 被看见 |
| 多米诺 | 30 块，越倒越快，约 2 秒倒完，最后一块撞响礼花筒 | 纯粹的连锁快感，不需要任何输入 |

投票时如果最近一分钟没人发过弹幕，只等 4 秒，糯糯自己选：冷清的直播间不会出现"所有人干等倒计时"。

盲盒概率：普通 58 / 稀有 30 / 史诗 10 / 传说 2（权重）；热度加成把普通的权重最多移走 30，分给稀有 +12、史诗 +11、传说 +7。没开到过的款有四分之三的机会优先出。挑战奖励的盲盒保底稀有。

## 5. 竖屏排版与镜头

抖音直播间的界面会盖住画面：最上面约 12%（主播信息、在线观众、关注按钮），下面约 38%（评论区、礼物动画、输入框、右下角的点赞）。所以竖屏下：

- **文字区**在 13%~37%：关卡 + 图鉴、应援条、进度点、提示 / 站名（左）+ 应援榜（右）。
- **主角区**在 37%~60%：糯糯、它头顶的气泡、提示条（最多同时两条，可折两行）。
- **60% 以下**只放地面、脚印和场景——被评论区盖住也不丢信息。
- 字号按"1080 宽的画面缩到手机上还清楚"定：竖屏以 720 为设计宽度，正文 28、标题 38~70。
- 同一块地方不同时出现两样东西：投票面板出现时应援榜让位；答谢横幅、关卡标题、揭晓卡片出现时提示和榜单淡出。

镜头：

- 走路、踩踏、正脸特写等机位都按**竖屏的宽度**重新算距离，糯糯居中、从耳朵尖到小脚完整入画。
- 新增"舞台构图"机位：给一个中心点、一个半径和一个方向，自动算出把这一片都装进竖屏的距离。悬念段落都用它——上面是糯糯的脸，下面是蛋 / 礼盒 / 地砖。
- 逐张截图审查后修掉的遮挡：投票面板改成一行小选项（原来的大面板会盖住糯糯）；礼盒编号印在盒子正面、「左」「右」写在地砖上（原来浮在空中的数字会挡住眼睛）；开出的手办往旁边飘、糯糯往另一边让半步；礼盒盖子改成弹飞（原来向后翻开，竖起来正好挡住糯糯的脸）；答谢横幅用整个屏幕宽度（原来只有半屏宽，名字被折行）。

## 6. 监听 v2：为什么之前没触发、现在怎么保证

真实直播间无法在开发环境里访问，所以这一节既是设计，也是**对不确定性的处理**：

| 可能的故障 | v1 的表现 | v2 的做法 |
|---|---|---|
| 弹幕连接的网址变了、或者连接建立在监听开始之前 | 认不出来，静默丢弃 | 不看网址：对**每一条二进制数据帧**都尝试按抖音的格式解码，解得出来的就是弹幕通道；监听在页面加载前就开始；Worker、iframe 里的连接自动附加 |
| 压缩方式变了 | 解压失败 | 支持 gzip / zstd / brotli，并记录见过的压缩方式 |
| 页面停在验证码 / 登录 / 未开播 / 找不到直播间 / 网络错误 | 没有任何提示 | 每 5 秒给页面做一次"体检"并分类；验证码自动把窗口弹出来；每种情况都有大白话的原因和解决办法 |
| 数据帧完全解不出来（协议大改） | 完全失效 | 备用通道：直接读页面聊天区的文字（"昵称：内容""昵称 来了""送出了 xx × 3"），至少弹幕、进房、点赞、礼物文字还能用 |
| 不拉视频流导致页面不建立连接 | 一直等 | 45 秒没数据自动放开视频流重试一次 |
| 出了问题说不清 | 只能猜 | 控制台实时小图（监听窗口看到了什么）+ 一键导出诊断（状态、各类消息计数、没处理的消息类型、最近日志） |
| 新的互动类型 | 忽略 | 新增加粉丝团、表情弹幕；没处理的消息类型会被计数，方便以后补 |

测试：`tools/test-listener.mjs` 用真实浏览器对着本机的模拟直播间跑 5 种情况（标准通道、陌生网址、Worker 里的连接、验证码页、只有页面文字）；`tools/selftest.mjs` 覆盖解码、识别、分类、过滤等纯逻辑。**它们都不是真实抖音**——真实环境以控制台的连接体检为准，这也是为什么体检和诊断做得这么重。

## 7. 没做的、以后可以做的

- **两队对抗**（弹幕选边、两边比应援）：成熟、带动性强，但会改变"治愈、合作"的调性，先没做。可以先从"左派 / 右派谁猜得准"的轻量统计开始。
- **每个观众一只小动物**（修勾夜店式）：参与感最强，也最吃性能和排版，竖屏里放不下很多角色；可以先做"应援榜前三名的小跟班"。
- **气球上升挑战**（大家点赞把糯糯吹上天）：想过，和终点宝箱的结构重复，没做。
- **官方接入**（抖音开放平台 · 直播小玩法）：最合规、最稳定的数据来源，需要按平台要求申请；现在的事件格式是通用的，以后换数据源不用改游戏。
- **夜间助眠模式**（更暗的画面、更慢的节奏、去掉倒计时）：适合深夜时段，值得做。
